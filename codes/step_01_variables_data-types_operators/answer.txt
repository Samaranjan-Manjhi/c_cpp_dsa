SECTION 1A — C++ BASICS & SYNTAX (20 QUESTIONS)
================================================================================

1) What is the difference between compiler and interpreter?
   A compiler translates the ENTIRE source code into machine code (an executable)
   before execution — errors are caught at compile time, and execution is fast
   since no translation happens at runtime. An interpreter translates and executes
   code line-by-line at runtime — easier to debug interactively, but slower.
   C++ is compiled; Python is interpreted (technically compiled to bytecode then
   interpreted by a VM).

2) What happens during compilation of a C++ program step by step?
   1. Preprocessing — macros expanded, #include files pasted in, conditional
      compilation resolved (#ifdef etc.) → produces a translation unit.
   2. Compilation — translation unit converted to assembly code, syntax/semantic
      checks done, then assembled into object code (.o/.obj) containing machine
      code with unresolved external symbols.
   3. Assembly — assembler converts assembly to machine code (binary object file).
   4. Linking — linker resolves references between object files and libraries
      (static or dynamic) and produces the final executable.
   5. Loading — OS loader loads the executable into memory for execution.

3) What is the difference between #include <file> and #include "file"?
   #include <file> tells the preprocessor to search standard system include
   directories first (used for standard/library headers).
   #include "file" tells it to search the current directory (relative to the
   including file) FIRST, then fall back to system directories (used for your
   own project headers).

4) What is a header guard? Why is it needed?
   A header guard prevents a header file from being included multiple times in
   the same translation unit, which would cause "redefinition" errors.
   Classic form:
       #ifndef MYHEADER_H
       #define MYHEADER_H
       ... contents ...
       #endif
   Modern equivalent: #pragma once (non-standard but supported everywhere).
   It's needed because headers can be included indirectly by multiple other
   headers, and without guards the compiler would see duplicate declarations.

5) What is the difference between declaration and definition?
   A declaration tells the compiler that something (a variable/function/class)
   EXISTS and what its type/signature is, without allocating storage or
   providing a body. A definition actually allocates storage / provides the
   function body.
   Example: "extern int x;" is a declaration. "int x;" is a definition.
   "int add(int,int);" is a declaration. "int add(int a,int b){return a+b;}"
   is a definition. A definition is also a declaration, but not vice versa.

6) What does return 0 mean in main()?
   It signals to the operating system that the program terminated successfully
   (EXIT_SUCCESS). A non-zero return value conventionally signals an error/
   abnormal termination, with the specific meaning of the code being OS/
   program-defined. If main() has no explicit return statement, the C++
   standard says it implicitly returns 0 (this is a special-case rule only
   for main()).

7) What is undefined behavior in C++? Give an example.
   Undefined behavior (UB) is behavior for which the C++ standard imposes NO
   requirements — the compiler is free to do anything: crash, produce garbage
   output, appear to "work," or optimize the code away entirely. It typically
   arises from things like: dereferencing a null/dangling pointer, signed
   integer overflow, accessing an array out of bounds, using an uninitialized
   variable, or modifying a variable twice between sequence points (e.g.
   i = i++ + ++i;). UB is dangerous precisely because it may appear to work
   correctly on one compiler/platform and fail on another.

8) What is the difference between i++ and ++i? Which is preferred and why?
   i++ (post-increment) returns the ORIGINAL value of i, then increments i.
   ++i (pre-increment) increments i FIRST, then returns the new value.
   For built-in types (int, etc.) there's no performance difference and both
   compile to the same code. For user-defined types (iterators, custom
   classes), ++i is generally preferred because post-increment must create
   and return a temporary copy of the old value (extra copy overhead), while
   pre-increment can just modify and return a reference. Convention: use ++i
   unless you specifically need the old value.

9) What is short-circuit evaluation in logical operators?
   In `a && b`, if 'a' is false, 'b' is never evaluated (result is guaranteed
   false already). In `a || b`, if 'a' is true, 'b' is never evaluated. This
   matters when the right-hand operand has side effects or could crash, e.g.:
       if (ptr != nullptr && ptr->value > 0)
   Here ptr->value is only evaluated if ptr is non-null, safely avoiding a
   null-pointer dereference.

10) What is the difference between = and == ? (Most common bug for beginners)
    '=' is the ASSIGNMENT operator — it assigns the right-hand value to the
    left-hand variable, e.g. x = 5.
    '==' is the EQUALITY comparison operator — it checks if two values are
    equal and returns a bool, e.g. x == 5.
    The classic bug: writing `if (x = 5)` instead of `if (x == 5)` — this
    assigns 5 to x, and since 5 is truthy, the if-block always executes,
    silently overwriting x. Most compilers warn about this ("suggest
    parentheses around assignment used as truth value").

11) Explain operator precedence with an example.
    Operator precedence determines the ORDER in which operators are applied
    in an expression without parentheses. Higher-precedence operators bind
    tighter. Example:
        int result = 2 + 3 * 4;   // = 2 + 12 = 14, NOT (2+3)*4 = 20
    because * has higher precedence than +. Associativity then decides order
    among operators of EQUAL precedence (e.g. + and - are left-to-right, so
    10 - 3 - 2 = (10-3)-2 = 5).

12) What is the difference between / and % operators?
    '/' is integer (or float) division, returning the QUOTIENT.
    '%' is the modulo operator, returning the REMAINDER of division (only
    defined for integer types in C++, not float/double).
    Example: 7 / 2 = 3 (integer division truncates), 7 % 2 = 1.
    For negative operands, the result of % follows the sign of the dividend
    in C++ (e.g. -7 % 2 = -1), per C++11 rules.

13) What is integer overflow? How do you prevent it?
    Integer overflow occurs when an arithmetic result exceeds the range that
    a given integer type can represent. For signed integers, overflow is
    UNDEFINED BEHAVIOR in C++ (unlike unsigned, which wraps around modulo
    2^n predictably). Example: INT_MAX + 1 for a 32-bit int is UB.
    Prevention: use a larger type (long long), check bounds before the
    operation (e.g. compare against INT_MAX - x before adding), use
    std::numeric_limits to know the range, or use safe/checked arithmetic
    libraries/intrinsics (e.g. __builtin_add_overflow).

14) What is the difference between int, long, long long?
    These are integer types differing in guaranteed MINIMUM size (actual
    size is implementation/platform-defined):
      int        — at least 16 bits, typically 32 bits on modern systems
      long       — at least 32 bits, often 32 bits on Windows / 64 bits on
                   Linux/macOS (LLP64 vs LP64 data models)
      long long  — at least 64 bits (guaranteed since C++11), used for large
                   numbers safely across platforms.
    Rule of thumb in competitive programming/DSA: use long long when values
    might exceed ~2 billion.

15) When would you use unsigned int over int?
    Use unsigned int when a value can never logically be negative and you
    want the full positive range (e.g. array sizes/indices, bit masks, byte
    counts, hardware register values). Caution: mixing signed and unsigned
    in comparisons/arithmetic causes implicit conversions that can silently
    introduce bugs (see Q "signed vs unsigned comparison" below), so many
    style guides (e.g. Google C++ style guide) recommend avoiding unsigned
    for general arithmetic and reserving it for bit manipulation.

16) What is the size of int on a 32-bit vs 64-bit system?
    On most modern 32-bit AND 64-bit systems, int is still 4 bytes (32 bits)
    — the "bitness" of the system refers mainly to pointer/address width, not
    the int size. What actually changes between platforms/data models:
      LP64 (Linux/macOS 64-bit): int=4, long=8, pointer=8 bytes
      LLP64 (Windows 64-bit):    int=4, long=4, pointer=8 bytes
    Always verify with sizeof() rather than assuming, since sizes are
    implementation-defined.

17) What is auto keyword in C++? When should you use it?
    auto tells the compiler to deduce the variable's type automatically from
    its initializer at compile time (it is NOT dynamic typing — the type is
    fixed once deduced). Useful for: long/complex types (iterators, template
    types, lambdas), reducing verbosity, and avoiding type mismatches when
    refactoring. Should be avoided when it hides important type information
    that hurts readability, or when it silently deduces an unintended type
    (e.g. auto x = 5 / 2; deduces int, not double).

18) What is the difference between const int x and int const x?
    They are IDENTICAL — both declare x as a constant int. const can appear
    either before or after the type it qualifies with no difference in
    meaning. The distinction matters more with pointers:
      const int* p       — pointer to const int (can't modify *p)
      int* const p        — const pointer to int (can't reassign p itself)
      const int* const p  — both: const pointer to const int

19) What is constexpr? How is it different from const?
    const means the value cannot be modified after initialization, but it
    CAN be initialized at runtime (e.g. const int x = someFunction();).
    constexpr means the value MUST be computable at COMPILE TIME, enabling
    the compiler to substitute it directly and use it in contexts requiring
    compile-time constants (array sizes, template arguments, etc.). Every
    constexpr variable is implicitly const, but not every const variable is
    constexpr.

20) What is a magic number? Why should you avoid it?
    A magic number is an unexplained literal numeric value hard-coded
    directly in code (e.g. `if (status == 7)`), whose meaning isn't obvious
    from context. Avoid it because it hurts readability (what does 7 mean?)
    and maintainability (if the value needs to change, you must hunt down
    every occurrence). Fix: replace with a named constant or enum, e.g.
    `constexpr int STATUS_APPROVED = 7;`.

SECTION 1B — TYPE SYSTEM & CONVERSIONS (21 QUESTIONS)
================================================================================

21) What are the storage classes in C/C++? Explain each.
    auto     — default storage class for local variables (automatic storage
               duration); rarely written explicitly today (auto keyword now
               means type inference instead).
    register — a hint to the compiler to store the variable in a CPU register
               for faster access; modern compilers largely ignore this hint
               and optimize automatically (deprecated as a keyword in C++17).
    static   — for local variables: retains its value between function calls
               (lives for the program's lifetime, initialized once). For
               global variables/functions: restricts linkage to the current
               translation unit (internal linkage).
    extern   — declares that a variable/function is DEFINED in another
               translation unit; used to share globals across files without
               redefining them.
    mutable  — allows a class member to be modified even inside a const
               member function (used e.g. for caching/lazy-init fields).

22) What does static mean for a local variable?
    A static local variable is allocated once (in the program's static/data
    segment, not the stack) and RETAINS its value between successive calls
    to the function, instead of being re-initialized every call. It's
    initialized only the first time control passes through its declaration.
    Example:
        void counter() { static int n = 0; n++; std::cout << n; }
    Calling counter() repeatedly prints 1, 2, 3, ... instead of always 1.

23) What does static mean for a global variable?
    A static global variable/function has INTERNAL LINKAGE — it is only
    visible within the translation unit (source file) it's defined in, and
    cannot be accessed via 'extern' from other files. This is the primary
    C-style way to achieve "private" scoping at file level (in modern C++,
    anonymous namespaces are preferred for this).

24) What is variable shadowing? Give an example.
    Shadowing happens when a variable declared in an inner scope has the
    SAME NAME as a variable in an outer scope, "hiding" the outer one within
    that inner scope. Example:
        int x = 10;
        {
            int x = 20;      // shadows outer x
            std::cout << x;  // prints 20
        }
        std::cout << x;      // prints 10
    It can cause subtle bugs and most compilers offer warnings for it
    (-Wshadow in GCC/Clang).

25) What is a namespace? How does it help avoid name collisions?
    A namespace is a declarative region that groups related names (classes,
    functions, variables) under a distinct identifier, allowing the SAME
    name to be reused in different namespaces without conflict. Example:
        namespace A { void foo(); }
        namespace B { void foo(); }
        A::foo(); B::foo();   // no collision, resolved by qualification
    This is essential in large codebases and when combining multiple
    libraries that might otherwise define identically-named symbols.

26) What is an anonymous namespace? How is it different from static?
    An anonymous (unnamed) namespace gives its contents internal linkage —
    visible only within that translation unit — similar to file-level
    'static'. It's the modern C++ idiom preferred over 'static' because it
    works uniformly for ALL entities (including types/classes, which static
    cannot restrict, since 'static' only applies to functions/variables, not
    to class/type declarations).
        namespace { int helper = 5; }   // only visible in this .cpp file

27) What are the 4 types of casts in C++?
    static_cast      — compile-time checked conversion between related types
                       (e.g. int to float, base* to derived* with care, enum
                       to int). No runtime type check.
    dynamic_cast     — runtime-checked conversion, primarily for safely
                       downcasting polymorphic pointers/references; returns
                       nullptr (pointer) or throws std::bad_cast (reference)
                       if the cast is invalid. Requires RTTI.
    const_cast       — adds or removes const/volatile qualification from a
                       type; does NOT change the underlying value's actual
                       constness.
    reinterpret_cast — low-level cast that reinterprets the bit pattern of
                       one type as another (e.g. pointer to integer); highly
                       platform-dependent and unsafe if misused.

28) When would you use static_cast vs reinterpret_cast?
    Use static_cast for conversions that are logically related and
    well-defined by the language (numeric conversions, upcasting in class
    hierarchies, void* to typed pointer, enum<->int). Use reinterpret_cast
    only for low-level, implementation-specific reinterpretation of raw bits
    (e.g. casting a pointer to an integer for hashing, or between unrelated
    pointer types in systems/embedded code) — it offers no safety checks and
    should be a last resort.

29) What is dynamic_cast? What is RTTI? What is its cost?
    dynamic_cast performs a runtime-checked cast, typically used to safely
    downcast a base-class pointer/reference to a derived class in a
    polymorphic hierarchy (i.e. the base class must have at least one
    virtual function). RTTI (Run-Time Type Information) is the mechanism the
    compiler embeds (typically via the vtable) that stores type information
    needed to make this runtime check possible, e.g. via typeid as well.
    Cost: dynamic_cast has runtime overhead (walking the class hierarchy /
    comparing type info) compared to the zero-cost static_cast, and requires
    RTTI to be enabled (some embedded/performance-critical codebases disable
    RTTI entirely to save memory and cycles).

30) What is const_cast? When is it safe to use?
    const_cast removes (or adds) the const/volatile qualifier from a
    pointer or reference. It is SAFE only when the underlying object was
    NOT originally declared const — e.g. you have a const pointer parameter
    to a function that internally you know refers to a non-const object,
    and you need to pass it to a legacy API expecting non-const. Using
    const_cast to modify an object that was ACTUALLY declared const is
    undefined behavior.

31) What is implicit type conversion? What is explicit?
    Implicit conversion happens automatically, performed by the compiler
    without any cast written by the programmer (e.g. int to double when
    passed to a function expecting double, or in mixed-type arithmetic).
    Explicit conversion is one the programmer deliberately requests using
    a cast (static_cast<double>(x)) or a constructor call, making the intent
    clear and avoiding accidental/unwanted conversions.

32) What is integer promotion in C?
    Integer promotion is the automatic conversion of smaller integer types
    (char, short, bool, and unscoped enums) to 'int' (or 'unsigned int' if
    int can't represent all values) whenever they're used in an expression.
    This happens before arithmetic/comparison operations are performed.
    Example: two 'char' variables added together are first promoted to int,
    and the addition happens in int precision, avoiding overflow of the
    narrower char type mid-calculation.

33) What is the difference between signed and unsigned arithmetic?
    Signed arithmetic operates on types that can represent negative values;
    overflow in signed arithmetic is UNDEFINED BEHAVIOR in C++.
    Unsigned arithmetic operates only on non-negative values and is defined
    to WRAP AROUND (modulo 2^n) on overflow/underflow — e.g. unsigned int
    x = 0; x--; gives a very large positive number (UINT_MAX), not -1,
    because unsigned arithmetic is modular by definition (well-defined,
    not UB).

34) What happens when you compare signed and unsigned integers?
    This is a classic pitfall. When comparing a signed and an unsigned
    integer of the same rank, the C++ "usual arithmetic conversions" rule
    implicitly converts the SIGNED value to UNSIGNED before comparing.
    Example:
        int a = -1;
        unsigned int b = 1;
        if (a < b) ... // FALSE! -1 is converted to a huge unsigned number
    This causes silent, hard-to-spot bugs, especially in loop conditions
    like `for (int i = arr.size()-1; i >= 0; i--)` where .size() returns
    an unsigned size_t, making `i >= 0` always true and the loop infinite/
    out-of-bounds if 'i' itself becomes unsigned through mixed typing.

35) What is narrowing conversion? How does C++11 handle it?
    A narrowing conversion is one that may lose information — e.g. double
    to int (loses fraction), int to char (may lose range), or a larger
    int type to a smaller one. In C++11, brace/list-initialization ({})
    disallows narrowing conversions at compile time (produces an error or
    at least a warning), whereas traditional '=' or '()' initialization
    silently allows them. Example:
        int x = 3.14;      // allowed, silently truncates to 3
        int y {3.14};      // COMPILE ERROR: narrowing conversion

36) What is std::numeric_limits? When would you use it?
    std::numeric_limits<T> is a template (from <limits>) that provides
    compile-time queryable properties of a numeric type T, such as its
    minimum/maximum representable value, precision (epsilon), whether it's
    signed, infinity support, etc. Used when you need PORTABLE bounds
    instead of hardcoding platform-specific macros like INT_MAX:
        int maxVal = std::numeric_limits<int>::max();
    Common uses: overflow checks, initializing a "running max/min" variable
    to the type's extreme value, and generic/templated numeric code.

37) What is NaN and Inf in floating point? How do you check for them?
    NaN (Not-a-Number) represents an undefined/unrepresentable result, e.g.
    0.0/0.0 or sqrt(-1) for real numbers. Inf represents a value that has
    overflowed to infinity, e.g. 1.0/0.0. Both are special bit patterns
    defined by the IEEE-754 floating-point standard. NaN has the unusual
    property that NaN == NaN is FALSE (any comparison with NaN is false
    except !=). Checked using <cmath>: std::isnan(x) and std::isinf(x).

38) What is the difference between float and double precision? How many
    decimal digits each can represent?
    float is (typically) a 32-bit IEEE-754 type offering about 6-7
    significant decimal digits of precision.
    double is (typically) a 64-bit IEEE-754 type offering about 15-16
    significant decimal digits of precision.
    double uses more memory and (on some platforms) is slower, but is
    strongly preferred whenever precision matters (e.g. scientific/financial
    calculations), since float's limited precision accumulates error faster.

39) What is epsilon comparison for floats? Why not use == for floats?
    Floating-point numbers cannot exactly represent most decimal fractions
    in binary (e.g. 0.1 has no exact binary representation), so arithmetic
    on floats/doubles accumulates tiny rounding errors. Directly comparing
    with == can fail even when two values are "mathematically" equal, e.g.
    0.1 + 0.2 == 0.3 is FALSE in C++. The fix is an "epsilon comparison":
    check that the absolute difference is smaller than a small tolerance:
        fabs(a - b) < 1e-9
    (Note: a fixed epsilon isn't perfect for very large or very small
    magnitudes — relative epsilon or std::numeric_limits<T>::epsilon()
    scaled comparisons are used for more rigorous cases.)

40) What is endianness? What is little-endian vs big-endian?
    Endianness describes the ORDER in which bytes of a multi-byte value are
    stored in memory. Little-endian stores the LEAST significant byte at
    the lowest memory address (e.g. x86/x64 architecture). Big-endian
    stores the MOST significant byte first (e.g. some network protocols,
    older architectures like older PowerPC). This matters for binary file
    formats, network communication (network byte order is big-endian), and
    low-level systems/embedded programming.

41) How do you check endianness of a machine in C?
    A common trick uses a union or pointer cast to inspect the byte layout
    of a known integer value:
        int num = 1;
        char *ptr = (char*)&num;
        if (*ptr == 1) printf("Little-endian");
        else printf("Big-endian");
    This works because on little-endian systems, the least-significant byte
    (which is '1') is stored first (at the lowest address, where *ptr
    points), while on big-endian the first byte would be 0.

42) What is the difference between signed and unsigned right shift?
    For UNSIGNED integers, >> is always a LOGICAL shift: zeros are shifted
    in from the left (most-significant end), regardless of the original bit
    values.
    For SIGNED integers, the behavior of >> on a negative number is
    IMPLEMENTATION-DEFINED in C++ pre-20 (most compilers implement it as an
    ARITHMETIC shift, i.e. sign-extending — the sign bit is replicated into
    the vacated high bits, preserving the sign). From C++20 onward, the
    standard mandates arithmetic right shift for signed integers, removing
    the ambiguity.

43) What is type promotion in C++? What happens when you add char + int?
    Type promotion/usual arithmetic conversion automatically converts
    "smaller" operand types to a common type before an operation. When you
    add a char and an int, the char is first PROMOTED to int (integer
    promotion), and the addition is performed as int + int, yielding an int
    result — you don't get a char result, even though one operand was char.

44) Why is float comparison with == dangerous? How do you fix it?
    (See Q39 above for the core reasoning.) Because binary floating-point
    representation cannot exactly store most decimal fractions, two
    mathematically-equal float expressions may differ by a tiny rounding
    error, causing == to incorrectly return false. Fix: compare using an
    epsilon/tolerance threshold: fabs(a - b) < epsilon, rather than exact
    equality.

45) What is the difference between NaN and Infinity in floating point? How
    do you check for them in C++?
    NaN represents an invalid/undefined numeric result (like 0.0/0.0);
    Infinity represents a value that has grown beyond the representable
    range (like 1.0/0.0, or overflow of a large computation). Both are
    special IEEE-754 bit patterns, distinct from ordinary numbers. Checked
    via <cmath>: std::isnan(x) detects NaN, std::isinf(x) detects positive
    or negative infinity.

46) What does the comma operator do in C++? Give a tricky example.
    The comma operator (,) evaluates its LEFT operand, discards the result,
    then evaluates and returns its RIGHT operand's value — it sequences two
    expressions into one, evaluated left to right. Tricky example:
        int x = (1, 2, 3);   // x = 3 (only the last value survives)
    Another common trap is in a for-loop's increment clause:
        for (int i = 0, j = 10; i < j; i++, j--)  // legitimate/idiomatic use
    But writing it inside array indexing or macros can create confusing,
    hard-to-read side effects, so it's rarely used outside for-loops.

47) What is integral promotion? What is the "usual arithmetic conversion"?
    Integral promotion (see Q32) converts small integer types (bool, char,
    short, unscoped enum) to int/unsigned int before use in expressions.
    "Usual arithmetic conversions" is the broader rule set applied to the
    OPERANDS of binary operators (+, -, *, /, comparisons, etc.) AFTER
    integral promotion — it determines the common type both operands are
    converted to, following a hierarchy (e.g. if one operand is double, the
    other converts to double; if one is unsigned long and the other signed
    int, the signed one converts to unsigned long, etc.). This is exactly
    the mechanism behind the signed/unsigned comparison pitfall in Q34.

48) What is the difference between char, signed char, and unsigned char?
    Are they all distinct types?
    Yes — in C++, char, signed char, and unsigned char are three DISTINCT
    types (even though plain 'char' behaves identically to either signed or
    unsigned char depending on the platform/compiler — this is
    implementation-defined). 'char' is typically used for representing
    characters/text; whether plain char is signed or unsigned by default is
    NOT guaranteed by the standard. signed char and unsigned char are
    explicitly signed/unsigned 1-byte integer types, often used for small
    numeric values or raw byte manipulation rather than characters.

49) Can you have a reference to a reference in C++? What about pointer to
    reference?
    No to both, directly. C++ does NOT allow references to references
    (int& & r) or pointers to references (int&* p) as direct syntax — these
    are illegal by the language grammar. However, "reference collapsing"
    rules DO apply in template/auto contexts (e.g. with universal
    references / forwarding references in templates), where combinations
    like T& & effectively collapse down to a single T& — this is how
    std::forward and perfect forwarding work internally. But you can't
    write such a type directly in ordinary code.

50) What is std::numeric_limits<int>::max() and when would you use it?
    It returns the maximum representable value for type int (typically
    2147483647 on platforms with 32-bit int), obtained portably rather than
    hardcoding INT_MAX. Common uses: initializing a variable meant to track
    the "minimum found so far" in an algorithm (set it to max() first, so
    any real value will be smaller), sentinel/boundary values in graph
    algorithms (e.g. Dijkstra's "infinity" distance), and overflow-safety
    checks.

51) What is the difference between {}-initialization and ()-initialization?
    What is narrowing conversion?
    ()-initialization (direct initialization, e.g. int x(5);) and
    =-initialization (copy initialization, int x = 5;) both permit implicit
    narrowing conversions silently (e.g. int x(3.9); truncates to 3 with no
    error). {}-initialization (uniform/brace/list initialization, e.g.
    int x{5};) is stricter: the compiler FORBIDS narrowing conversions and
    will raise a compile error/warning if information could be lost, e.g.
    int x{3.9}; fails to compile. Brace initialization also avoids the
    "most vexing parse" ambiguity that can occur with (), and works
    uniformly across built-in types, arrays, and class types via
    initializer lists. (Narrowing conversion itself is defined in Q35.)

SECTION 2 — TRICKY / CURVEBALL QUESTIONS INTERVIEWERS ASK IN REAL TIME
     (Beyond the standard question bank — these test if you truly
      understand the concept, not just memorized definitions)
================================================================================

1. "What does this print?"  int x = 5; std::cout << x++ + ++x;
   → Tests understanding that modifying a variable more than once between
     sequence points without a defined order is UNDEFINED BEHAVIOR in C++
     (pre-C++17 evaluation order of operands is unspecified). The "correct"
     answer is: this is UB — don't rely on a specific numeric output, and
     real production code should never write expressions like this.

2. "Why does 0.1 + 0.2 != 0.3 in C++, but it looks like it should?"
   → Interviewer is checking if you understand binary floating-point
     representation, not just that you "know to use epsilon." Be ready to
     explain that 0.1 and 0.2 have no exact finite binary representation
     (like 1/3 in decimal), so tiny rounding errors compound.

3. "If int is 4 bytes, why doesn't sizeof always equal 4 on every machine?"
   → Tests whether you know sizes are IMPLEMENTATION-DEFINED, not
     guaranteed by the standard — only MINIMUM ranges are guaranteed.

4. "What's wrong with this loop?"
       for (int i = arr.size() - 1; i >= 0; i--)
   → Classic trap: arr.size() returns size_t (unsigned). If the vector is
     empty, size() - 1 underflows to a huge positive number BEFORE it's
     even assigned to i, causing undefined behavior/crash, not a clean
     "loop doesn't execute."

5. "Is `a = a + b` always the same as `a += b`?"
   → Usually yes for simple built-in types, but interviewers use this to
     probe if you know that for user-defined types (operator overloading),
     += can be implemented more efficiently (avoids creating a temporary),
     and that they are NOT guaranteed identical unless explicitly
     implemented that way.

6. "Can two pointers of different types point to the same memory address
   safely?"
   → Tests understanding of strict aliasing rules — accessing the same
     memory through incompatible pointer types (except char*) is undefined
     behavior, even if the addresses match numerically.

7. "What happens if you left-shift a negative number, or shift by more bits
   than the type's width (e.g. 1 << 32 on a 32-bit int)?"
   → Both are UNDEFINED BEHAVIOR in C++. Interviewers ask this to see if
     you blindly assume shifts "just work" like in higher-level languages.

8. "Why might `short x = 65536;` not immediately error, but still be wrong?"
   → Tests understanding of implicit narrowing via '=' (silently wraps/
     truncates) versus brace-init `short x{65536};` which WOULD be a
     compile error — probing whether you know the difference and prefer
     safer initialization habits.

9. "If a function takes an unsigned int parameter, and you pass -1, what
   happens?"
   → -1 is implicitly converted to unsigned, becoming UINT_MAX (a huge
     positive number), not an error. This is a favorite "gotcha" for
     testing signed/unsigned conversion understanding in real interviews.

10. "Is const_cast + modifying a const variable always undefined behavior,
    or only sometimes?"
    → Tests nuance: modifying via const_cast is UB ONLY if the object was
      ORIGINALLY declared const. If the underlying object is actually
      non-const (just accessed through a const-qualified pointer/reference),
      modifying it via const_cast is legal.

11. "What's the difference between a compile-time error and a linker
    error — can you give an example of each from something as simple as
    variables?"
    → Tests whether you actually understand the multi-stage build pipeline
      (Q2) rather than treating "build errors" as one bucket. E.g. missing
      semicolon = compile error; declaring `extern int x;` but never
      defining x anywhere = linker error ("undefined reference").

12. "Why is it risky to compare a float loop counter incrementing by 0.1
    against a target value, like `for (float f=0; f != 1.0; f += 0.1)`?"
    → Tests whether you connect float imprecision (Q39) to REAL bugs like
      infinite loops, since f may never exactly equal 1.0 due to rounding
      error accumulation — the loop could run forever or overshoot.

13. "If you don't initialize a local int variable, what value does it
    have?"
    → It contains INDETERMINATE/garbage memory content (whatever was there
      before) — reading it before assigning is undefined behavior, not
      guaranteed to be zero (unlike global/static variables, which ARE
      zero-initialized by default).

14. "Explain why `char` alone being signed or unsigned is a trick
    question."
    → As covered in Q48 — plain char's signedness is implementation-defined,
      so code that assumes char is always signed (e.g. for bit manipulation
      of raw bytes) can behave differently across compilers/platforms.

15. "What's the output of `std::cout << (5 == 5.0);` and why does it even
    compile if types differ?"
    → Tests understanding of implicit conversion — the int 5 is promoted to
      double for the comparison via usual arithmetic conversions, so it
      compiles and correctly prints 1 (true).

16. "Can constexpr functions/variables still fail at runtime?"
    → Nuance check: a constexpr variable/function CAN be evaluated at
      runtime too if the context doesn't require a compile-time constant
      (e.g. called with non-constant arguments) — constexpr means "CAN be
      evaluated at compile time," not "always is."

17. "If two variables in different translation units are both declared
    `static const int x = 5;`, is that a linker error?"
    → No — static gives internal linkage, so each translation unit gets its
      own independent copy; no collision occurs. This tests deeper
      understanding of linkage (Q23) versus a superficial "static = can't
      have duplicates" assumption.

18. "Why might `sizeof(x++)` not actually increment x?"
    → Classic gotcha: sizeof is (usually) evaluated at COMPILE TIME for
      built-in types and its operand is NOT evaluated at runtime, so
      side-effecting expressions inside sizeof() don't execute — x remains
      unchanged. (Exception: sizeof on a variable-length array in C, or
      certain VLA-adjacent contexts, does evaluate — a good follow-up
      nuance for senior candidates.)
