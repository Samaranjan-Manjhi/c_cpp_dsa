--- OOP IN C++ (will definitely be asked) ---

Q1. What are the 4 pillars of OOP?
A:  1. Encapsulation  — hide data inside classes (private members)
    2. Abstraction    — expose only what's needed (interfaces/virtual)
    3. Inheritance    — child reuses parent class
    4. Polymorphism   — same call, different behavior at runtime

Q2. Virtual function vs pure virtual function?
A:  Virtual      = has a default body, child CAN override
    Pure virtual = "= 0", no body, class is abstract, child MUST override
    class Shape {
        virtual void draw() {}        // can override
        virtual double area() = 0;    // must override — Shape is abstract
    };

Q3. What is vtable?
A:  Compiler creates a hidden table of function pointers per class.
    When you call a virtual function via base pointer, the runtime looks
    up the vtable to find the correct derived class function.
    This is how polymorphism works under the hood.
    Base* b = new Derived(); b->show(); // vtable lookup → calls Derived::show()

Q4. What is RAII? (link to your project!)
A:  Resource Acquisition Is Initialization. Tie resource lifetime to
    object lifetime. Constructor acquires, destructor releases.
    Prevents leaks even on exceptions.
    class FileHandle {
        FILE* f;
    public:
        FileHandle(const char* p) { f = fopen(p,"r"); }
        ~FileHandle() { if(f) fclose(f); }  // auto-close
    };
    YOUR ANSWER: "In my DLP scanner I use RAII wrappers around SQLite3
    handles — they auto-close on any exit path including exceptions."

Q5. Smart pointers — unique_ptr vs shared_ptr vs weak_ptr?
A:  unique_ptr = sole ownership, not copyable, zero overhead
    shared_ptr  = shared ownership via reference count
    weak_ptr    = non-owning reference to shared_ptr, breaks cycles
    When: unique_ptr by default. shared_ptr only when ownership is shared.
    weak_ptr to avoid cyclic references (A→B→A would never free).

Q6. Rule of 5?
A:  If you define any of: destructor, copy constructor, copy assignment,
    move constructor, move assignment — define all 5.
    Why: compiler-generated ones do shallow copy → double free on raw pointers.

Q7. Struct vs class in C++?
A:  Only difference: default access.
    struct = public by default.
    class  = private by default.
    Otherwise identical — both can have constructors, methods, inheritance.

Q8. Diamond problem?
A:  B and C both inherit A. D inherits B and C. D has two copies of A.
    Fix: virtual inheritance — class B : virtual public A;
    Now only one copy of A exists in D.

Q9. Deep copy vs shallow copy?
A:  Shallow copy: copies pointer (both point to same memory → double free)
    Deep copy: copies the data the pointer points to (independent copy)
    Relevant: default copy constructor does shallow copy — dangerous for
    classes owning heap memory.


--- OS INTERNALS (universal — same on Linux and Windows) ---

Q1. What happens when exec() is called?
A:  1. Kernel finds the binary on disk
    2. Checks permissions + reads ELF header
    3. Loads program segments into virtual memory
    4. Sets up stack, heap, BSS
    5. Transfers control to entry point (_start → main)
    YOUR ANSWER: "In MW Guardian, fanotify FAN_OPEN_PERM intercepts
    exec() at step 2 — we verify the Ed25519 signature BEFORE the
    binary gets to step 3. Tampered binary = SIGKILL."

Q2. Process vs thread?
A:  Process: independent address space, own file descriptors, own PID.
    Thread: shares address space and file descriptors with other threads
    of the same process. Lighter to create and switch.
    YOUR ANSWER: "In MW Guardian the fanotify event loop runs on one
    thread, Unix socket IPC server on another — shared queue protected
    by mutex."

Q3. What is a system call? How does your ftrace work?
A:  Syscall: user-space requests kernel service. CPU switches from ring 3
    (user) to ring 0 (kernel), executes, returns.
    ftrace: kernel's built-in function tracer. Register a callback that
    fires before/after any kernel function — including sys_rename.
    No kernel recompile needed. Your answer: "I hooked sys_rename via
    ftrace in my ransomware module. Bulk renames exceeding threshold →
    SIGKILL offending PID + JSON log to dmesg."

Q4. Virtual memory and page tables?
A:  Each process sees a private 64-bit address space. OS maps virtual
    addresses to physical RAM via page tables. TLB caches recent mappings.
    Page fault: virtual address not mapped → OS loads page from disk.

Q5. Stack vs heap?
A:  Stack: auto-managed, LIFO, limited size, fast. Local variables.
    Heap:  manual (malloc/new), unlimited (RAM), slower. Dynamic objects.
    Stack overflow: deep recursion. Heap leak: forgot to free/delete.

--- MULTITHREADING & IPC ---

Q1. Mutex vs semaphore?
A:  Mutex: ownership — only the locker can unlock. Binary. Mutual exclusion.
    Semaphore: no ownership — any thread can signal. Counting (0 to N).
    Use semaphore for: limiting concurrent DB connections, signaling events.
    Use mutex for: protecting a shared data structure.

Q2. Deadlock — 4 Coffman conditions?
A:  1. Mutual exclusion — resource held by only one thread
    2. Hold and wait   — holding one resource, waiting for another
    3. No preemption   — resource can't be taken forcibly
    4. Circular wait   — A waits for B, B waits for A
    Break ANY one condition → no deadlock possible.

Q3. Race condition?
A:  Two threads access shared data without synchronization.
    Result is non-deterministic. Fix: mutex or atomic operations.

Q4. select vs poll vs epoll?
A:  select: limited FDs, slow (O(n) scan)
    poll:   no FD limit, still O(n) scan
    epoll:  O(1) — kernel notifies only active FDs. Used in high-perf servers.
    YOUR ANSWER: "In my Content Scanner Unix socket server I used
    epoll to handle multiple client connections without blocking."

Q5. condition_variable — when to use?
A:  When one thread must wait for a condition set by another thread.
    Producer-consumer: consumer waits on cv.wait() until producer pushes.
    std::unique_lock<std::mutex> lk(mtx);
    cv.wait(lk, [&]{ return !queue.empty(); });

ListNode* reverse(ListNode* head) {
    ListNode *prev = nullptr, *curr = head, *next;
    while(curr) {
        next = curr->next;
        curr->next = prev;

    while(fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;

3. LONGEST SUBSTRING WITHOUT REPEATING CHARS (likely)
int lengthOfLongestSubstring(string s) {
    unordered_set<char> seen;
    int left=0, maxLen=0;
    for(int right=0; right<s.size(); right++) {
        while(seen.count(s[right]))
            seen.erase(s[left++]);
        seen.insert(s[right]);
        maxLen = max(maxLen, right-left+1);
    }
    return maxLen;
}
Time O(n), Space O(n). "abcabcbb" → 3 ("abc")

4. TWO SUM (easy warm-up)
vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int,int> mp;
    for(int i=0; i<nums.size(); i++) {
        int comp = target - nums[i];
        if(mp.count(comp)) return {mp[comp], i};
        mp[nums[i]] = i;
    }
    return {};
}
Time O(n). Don't do the O(n²) brute force.

5. THREAD-SAFE PRODUCER-CONSUMER QUEUE (possible — directly from your work)
template<typename T>
class SafeQueue {
    queue<T> q;
    mutex mtx;
    condition_variable cv;
public:
    void push(T val) {
        unique_lock<mutex> lk(mtx);
        q.push(val);
        cv.notify_one();
    }
    T pop() {
        unique_lock<mutex> lk(mtx);
        cv.wait(lk, [&]{ return !q.empty(); });
        T val = q.front(); q.pop();
        return val;
    }
};

bool isValid(string s) {
    stack<char> st;
    for(char c : s) {
        if(c=='('||c=='{'||c=='[') st.push(c);
        else {
            if(st.empty()) return false;
            char top=st.top(); st.pop();
            if(c==')'&&top!='(') return false;

7. BINARY SEARCH ON ROTATED SORTED ARRAY (medium — possible)
int search(vector<int>& nums, int target) {
    int lo=0, hi=nums.size()-1;
    while(lo<=hi) {
        int mid=(lo+hi)/2;
        if(nums[mid]==target) return mid;
        if(nums[lo]<=nums[mid]) {   // left half sorted
            if(nums[lo]<=target && target<nums[mid]) hi=mid-1;
            else lo=mid+1;
        } else {                     // right half sorted
            if(nums[mid]<target && target<=nums[hi]) lo=mid+1;
            else hi=mid-1;
        }
    }
    return -1;
}

8. LEVEL ORDER TRAVERSAL OF BINARY TREE (medium)
vector<vector<int>> levelOrder(TreeNode* root) {
    vector<vector<int>> res;
    if(!root) return res;
    queue<TreeNode*> q;
    q.push(root);
    while(!q.empty()) {
        int sz=q.size();
        vector<int> level;
        for(int i=0;i<sz;i++) {
            auto node=q.front(); q.pop();
            level.push_back(node->val);
            if(node->left) q.push(node->left);
            if(node->right) q.push(node->right);
        }
        res.push_back(level);
    }
    return res;
}
