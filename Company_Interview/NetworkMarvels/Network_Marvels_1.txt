Q. Types of polymorphism in C++?
Ans: Compile-time (static): function overloading, operator overloading — resolved at compile time.
     Runtime (dynamic): virtual functions + inheritance — resolved at runtime via vtable.
// Compile-time
int add(int a, int b) { return a+b; }
float add(float a, float b) { return a+b; }

// Runtime
class Base { public: virtual void show() {} };
class Derived : public Base {
  public: void show() override { cout << "Derived"; }
};
Base* b = new Derived();
b->show(); // calls Derived::show() via vtable

  virtual double area() = 0;        // pure virtual — must override

Q. Mutex vs Semaphore — key difference?
Ans: Mutex: ownership — only the thread that locked it can unlock it. Binary (locked/unlocked). Used for mutual exclusion.
Semaphore: no ownership — any thread can signal. Can be counting (0 to N). Used for signaling between threads or limiting access to N resources.
// Mutex
std::mutex mtx;
mtx.lock();   // only this thread can unlock
mtx.unlock();

// Semaphore (C++20)
std::counting_semaphore<5> sem(5); // allow 5 concurrent
sem.acquire();
sem.release();


Q. What is deadlock? 4 conditions for deadlock? 
Ans: Deadlock: two or more threads waiting for each other forever. 4 conditions (all must hold simultaneously):
1. Mutual exclusion — resource held by only one thread
2. Hold and wait — holding one, waiting for another
3. No preemption — resource can't be taken forcibly
4. Circular wait — A waits for B, B waits for A

Q. Reverse a linked list (iterative)
Ans: 
Use 3 pointers: prev, curr, next. Move through list reversing each pointer.
ListNode* reverse(ListNode* head) 
{
    ListNode *prev = nullptr, *curr = head, *next;
    while(curr) 
    {
        next = curr->next;   // save next
        curr->next = prev;   // reverse link
        prev = curr;         // move prev
        curr = next;         // move curr
    }
    return prev;             // new head
}
Time: O(n), Space: O(1). Trace it on paper: 1→2→3→null becomes null←1←2←3


Q. Find middle of a linked list
Ans: 
ListNode* findMiddle(ListNode* head) 
{
    ListNode *slow = head, *fast = head;
    while(fast && fast->next) 
    {
        slow = slow->next;
        fast = fast->next->next;
    }
    return slow; // slow is at middle
}


Q. Detect cycle in a linked list (Floyd's algorithm)
Ans: 
Two pointers: slow moves 1 step, fast moves 2 steps. If they meet, cycle exists.
bool hasCycle(ListNode* head) 
{
    ListNode *slow = head, *fast = head;
    while(fast && fast->next) 
    {
        slow = slow->next;
        fast = fast->next->next;
        if(slow == fast) return true;
    }
    return false;
}
Time: O(n), Space: O(1). If asked "find where cycle starts" — reset slow to head, move both 1 step at a time until they meet again.


Q. Lowest Common Ancestor (LCA) of binary tree
Ans: 
If current node is null or equals p or q, return it. Recurse left and right. If both sides return non-null, current node is LCA. If only one side, return that side.
TreeNode* lca(TreeNode* root, TreeNode* p, TreeNode* q) 
{
    if(!root || root==p || root==q) return root;
    TreeNode* left  = lca(root->left,  p, q);
    TreeNode* right = lca(root->right, p, q);
    if(left && right) return root;  // p and q on different sides
    return left ? left : right;
}
Time: O(n), Space: O(h). For BST (not general binary tree), can do it faster using BST property.


Q. Level order traversal (BFS on tree)
Ans: 
vector<vector<int>> levelOrder(TreeNode* root) 
{
    vector<vector<int>> res;
    if(!root) return res;
    queue<TreeNode*> q;
    q.push(root);
    while(!q.empty()) 
    {
        int sz = q.size();
        vector<int> level;
        for(int i=0; i<sz; i++) 
        {
            auto node = q.front(); q.pop();
            level.push_back(node->val);
            if(node->left)  q.push(node->left);
            if(node->right) q.push(node->right);
        }
        res.push_back(level);
    }
    return res;
}


Q. Longest substring without repeating characters
Ans: 
Sliding window with a set. Expand right, shrink left when duplicate found.
int lengthOfLongestSubstring(string s) 
{
    unordered_set<char> seen;
    int left=0, maxLen=0;
    for(int right=0; right<s.size(); right++) 
    {
        while(seen.count(s[right]))
            seen.erase(s[left++]);
        seen.insert(s[right]);
        maxLen = max(maxLen, right-left+1);
    }
    return maxLen;
}
Time: O(n), Space: O(min(n, alphabet)). For "abcabcbb" → answer is 3 ("abc").



Q. Two sum — find pair that adds to target
Ans: 
vector<int> twoSum(vector<int>& nums, int target) 
{
    unordered_map<int,int> mp; // val → index
    for(int i=0; i<nums.size(); i++) 
    {
        int complement = target - nums[i];
        if(mp.count(complement))
            return {mp[complement], i};
        mp[nums[i]] = i;
    }
    return {};
}
Time: O(n), Space: O(n). Better than brute force O(n²).

Q. Difference between WHERE and HAVING? (MUST KNOW)
Ans: 
WHERE filters rows BEFORE grouping. HAVING filters groups AFTER GROUP BY. You cannot use aggregate functions (SUM, COUNT) in WHERE.
-- Find departments with more than 5 employees
SELECT department, COUNT(*) as cnt
FROM employees
WHERE status = 'active'        -- filters rows first
GROUP BY department
HAVING COUNT(*) > 5;           -- filters groups after


Q. Types of JOINs — explain with example (MUST KNOW)
Ans: 
INNER JOIN: only matching rows from both tables.
LEFT JOIN: all rows from left + matching from right (NULL if no match).
RIGHT JOIN: all rows from right + matching from left.
FULL OUTER JOIN: all rows from both, NULL where no match.

LEFT JOIN departments d ON e.dept_id = d.id;
Most common follow-up: "When would you use LEFT JOIN over INNER JOIN?" — Answer: when you want rows from the left table even if there's no matching row on the right (e.g., employees with no assigned project).

Q: What is a virtual function? How does vtable work?

A virtual function enables runtime polymorphism. When a class has virtual functions, the compiler creates a vtable — a table of function pointers to the actual method implementations. Each object has a hidden vptr (virtual pointer) that points to its class's vtable. When you call a virtual function on a base pointer, the vptr resolves which implementation to call at runtime. Derived classes override their vtable entries.
Q: Difference between abstract class and interface in C++?

In C++, an abstract class has at least one pure virtual function (declared with = 0). A class that has all pure virtual functions acts as an interface. A concrete derived class must implement all pure virtual functions, otherwise it also becomes abstract. C++ has no separate "interface" keyword unlike Java.
Q: What is the diamond problem? How does C++ solve it?

Diamond problem occurs in multiple inheritance when two parent classes inherit from the same base class, causing ambiguity about which copy of the base to use. C++ solves it via virtual inheritance — when you declare the base as virtual in both parent classes, only one shared instance of the base class is created, eliminating the ambiguity.
Q: Explain memory layout of a C++ object.

Member variables are laid out in declaration order. If the class has virtual functions, a vptr is placed at the beginning. In inheritance, the base class subobject comes first, followed by derived class members. The compiler may add padding for alignment. For virtual inheritance, an additional vbptr (virtual base pointer) is added.

BFS: shortest path in unweighted graph, level-order traversal, uses a queue. Good when answer is close to root.
DFS: cycle detection, topological sort, path finding in deep trees, uses stack or recursion. Good for exhaustive search.

Q: Find LCA of two nodes in a binary tree.
Node* lca(Node* root, Node* p, Node* q) {
    if (!root || root == p || root == q) return root;
    Node* left = lca(root->left, p, q);
    Node* right = lca(root->right, p, q);
    if (left && right) return root;
    return left ? left : right;
}
Time: O(n)
Q: Detect cycle in a linked list.

Floyd's cycle detection — slow pointer moves 1 step, fast pointer moves 2 steps. If they meet, a cycle exists.
bool hasCycle(Node* head) {
    Node* slow = head;
    Node* fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;
    }
    return false;
}
Time: O(n), Space: O(1)
Q: Find the Kth largest element in an array.

Use a min-heap of size K. Iterate array — if element > heap top, replace top and heapify. After full iteration, top is Kth largest. Time: O(n log K).

TECHNICAL QUESTIONS — OS INTERNALS
Q: Difference between process and thread?

Process: independent memory address space, own file descriptors and resources, heavier context switch. Thread: shares the process memory and file descriptors, lighter context switch, faster to create. You ran multithreaded C++ daemons — mention your fanotify event loop with worker threads processing events concurrently.
Q: What is a deadlock? Four conditions and prevention?

Four conditions (Coffman conditions): mutual exclusion, hold-and-wait, no preemption, circular wait.

Prevention strategies: lock ordering (always acquire locks in the same fixed order), try-lock with timeout to break hold-and-wait, avoid nested locks. In your daemon, mention using a consistent lock order across mutexes.
Q: Explain virtual memory and page fault.

Each process has a virtual address space mapped to physical RAM via page tables maintained by the OS. A page fault occurs when the CPU accesses a virtual address whose page is not currently in physical memory. The OS kernel handles it by locating the page (on disk/swap), loading it into RAM, updating the page table, and resuming the process. Hard fault = load from swap. Soft fault = page in memory but not mapped yet.
Q: What is a context switch?

Saving the CPU state (registers, program counter, stack pointer) of the currently running process/thread and restoring the saved state of the next one. Triggered by scheduler preemption, I/O wait, or system calls. Threads are cheaper to switch because they share virtual memory — only registers and stack change.
Q: Explain how fanotify works at the kernel level.

fanotify is a Linux kernel subsystem for filesystem event notification and permission control. Your daemon opens a fanotify group with fanotify_init(), then marks paths or mount points with fanotify_mark(). FAN_OPEN_PERM causes the kernel to block the opening syscall — the process waits until your daemon reads the event and writes back FAN_ALLOW or FAN_DENY. FAN_ACCESS_PERM does the same for reads. Your Guardian uses this to freeze binaries at exec() and verify Ed25519 signatures before allowing execution.
Q: What is a semaphore vs mutex?

Mutex: binary lock owned by the thread that acquired it — only that thread can release it. Used for mutual exclusion. Semaphore: signaling primitive with a counter — one thread can signal and another can wait, no ownership concept. Use mutex for protecting shared resources; use semaphore for signaling between threads (producer-consumer).

Clustered index: the data rows are physically sorted and stored in the order of the index key. Only one per table (usually primary key). INNER JOIN: only rows with matching values in both tables. LEFT JOIN: all rows from left table, nulls for unmatched right. RIGHT JOIN: opposite. FULL OUTER JOIN: all rows from both, nulls where no match. CROSS JOIN: Cartesian product of both tables.

2C. MEMORY & POINTERS (Deep level — relevant to your kernel work)
Q: What is memory alignment? Why does it matter?

CPU reads memory in aligned chunks (4 or 8 bytes). Misaligned access causes extra reads or a hardware trap. Compilers add padding to structs to maintain alignment. Critical in your kernel structs and packed network packets.
Q: What is the difference between shallow copy and deep copy?

Shallow copy: copies the pointer value — both objects point to same memory. Deep copy: allocates new memory and copies the actual data. Shallow copy causes double-free crashes.
Q: What causes a segfault?

Dereferencing null/invalid pointer, accessing freed memory, stack overflow (infinite recursion), writing to read-only memory, buffer overflow past array bounds.
Q: What is buffer overflow? How do you prevent it?

Writing beyond the end of a fixed-size buffer, overwriting adjacent memory (return addresses, stack canaries). Prevention: use strncpy instead of strcpy, bounds checking, stack canaries (compiler flag -fstack-protector), ASLR, NX bit.
Q: What is a race condition?

When output depends on the timing/order of thread execution. Two threads read-modify-write the same variable without synchronization. Fix: mutex, atomic operations, lock-free data structures.

exec() replaces the current process image with a new program. Kernel loads the new binary, sets up new stack with arguments, resets instruction pointer to entry point. Does not create a new process — same PID. Your Guardian intercepts this moment via fanotify FAN_OPEN_PERM.
Q: What is the difference between fork() and exec()?

fork(): creates a new child process (copy of parent). exec(): replaces current process with a new program. Typically used together — fork to create child, exec in child to run new program.
Q: What is mmap()?

Maps a file or device into the process's virtual address space. Allows file I/O via memory reads/writes instead of read()/write() syscalls. Also used for shared memory between processes.
Q: What is the difference between hard link and soft link?

Hard link: another directory entry pointing to the same inode. Same data, same inode number. Survives deletion of original file.

Soft link (symlink): a file containing the path to the target. Different inode. Breaks if original is deleted.
Q: What is an inode?

Data structure storing file metadata — size, permissions, owner, timestamps, and pointers to data blocks. Does NOT store the filename. Directory entries map filenames to inodes.
Q: What is a kernel module (.ko)?

Code that can be loaded into and unloaded from the running kernel dynamically without rebooting. Your ransomware detector and Guardian are kernel modules. Loaded with insmod, removed with rmmod, listed with lsmod.
Q: What is the difference between user space and kernel space?

Kernel space: privileged mode, full hardware access, shared address space, a crash brings down the system. User space: restricted mode, isolated address space, crashes only affect that process. Transitions via system calls, interrupts, exceptions.
Q: What is ioctl()?

General-purpose system call for device-specific control operations. Used to communicate with device drivers/kernel modules. You expose sysfs interface in your ransomware module — ioctl is the alternative approach.
Q: What is ftrace? How did you use it?

Linux kernel tracing framework. Allows hooking kernel functions by replacing their first bytes with a call to a trampoline. Your ransomware module uses ftrace to hook sys_rename, sys_execve, sys_open — you store original function pointer, replace with your hook, call original inside hook.

PUZZLE 1: Tower of Hanoi
Problem: Move n disks from peg A to peg C using peg B. Never place larger disk on smaller.
Solution (recursive):
To move n disks from A to C using B:
1. Move n-1 disks from A to B (using C as auxiliary)
2. Move the nth (largest) disk from A to C
3. Move n-1 disks from B to C (using A as auxiliary)
void hanoi(int n, char from, char to, char aux) {
    if (n == 1) {
        printf("Move disk 1 from %c to %c\n", from, to);
        return;
    }
    hanoi(n-1, from, aux, to);
    printf("Move disk %d from %c to %c\n", n, from, to);
    hanoi(n-1, aux, to, from);
}

Time complexity: O(2^n)

int binarySearch(int arr[], int n, int target) {

    while (lo <= hi) {

        else hi = mid - 1;

SECTION 7 — QUICK REFERENCE ANSWERS FOR INTERVIEW
What is an API?

Application Programming Interface — a defined set of functions/protocols that allows two programs to communicate. REST API uses HTTP, OS API (Win32/POSIX) provides syscalls.
What is endianness?

Byte order in multi-byte values. Little-endian: least significant byte at lowest address (x86, most modern CPUs). Big-endian: most significant byte first (network byte order). Your kernel structs must handle this when reading network packets.
What is a mutex vs spinlock?

What is the difference between a process and a daemon?

What is volatile keyword?

Hints to compiler that a pointer is the only pointer accessing that memory — enables more aggressive optimization. Used in memcpy, string functions.

SECTION 8 — ADVANCED C++ (They will ask these for 3-year experience)

8A. CONSTRUCTORS & DESTRUCTORS
Q: What is the order of constructor/destructor calls in inheritance?

Constructor: Base first, then Derived.

Destructor: Derived first, then Base.

Always make base class destructor virtual if using polymorphism — otherwise deleting via base pointer won't call derived destructor (memory leak / undefined behaviour).
class A {
public:
    A()  { cout << "A constructor\n"; }
    virtual ~A() { cout << "A destructor\n"; }
};
class B : public A {
public:
    B()  { cout << "B constructor\n"; }
    ~B() { cout << "B destructor\n"; }
};
// Output when B obj created and destroyed:
// A constructor → B constructor → B destructor → A destructor
Q: What is a delegating constructor? (C++11)

A constructor that calls another constructor of the same class.
class MyClass {
    int x, y;
public:
    MyClass(int x, int y) : x(x), y(y) {}
    MyClass(int x) : MyClass(x, 0) {}  // delegates to above
};
Q: What is an initializer list? Why is it preferred?

Initializes members before constructor body runs. Required for: const members, reference members, base class constructors, objects without default constructor. More efficient — avoids default-init + assignment.
MyClass(int a, int b) : x(a), y(b) {}  // initializer list
Q: When is a destructor NOT called?

When program calls exit() or abort(). When process is killed with SIGKILL. When destructor itself throws. When using placement new without explicit destructor call. Important for your daemon shutdown logic.

8B. INHERITANCE & POLYMORPHISM
Q: What is object slicing?

When a derived object is assigned to a base object (by value), the derived-specific members are "sliced off". Only base part is copied. Fix: always use pointers or references when working with polymorphism.
Dog d;
Animal a = d;  // slicing — Dog's bark() is lost
Animal &a = d; // correct — no slicing, polymorphism works
Q: What is a pure virtual function? Can you have a pure virtual destructor?

Pure virtual: virtual void func() = 0; — makes class abstract, forces derived to implement.

Pure virtual destructor: yes, but you must still provide a definition (the chain needs to call it).
virtual ~Base() = 0;
Base::~Base() {}  // must define even though pure virtual
Q: What is multiple inheritance? What problems does it cause?

A class inheriting from more than one base class. Problems: diamond problem (ambiguity), increased complexity, name conflicts. Solved with virtual inheritance. C++ supports it; Java/C# avoid it by allowing only single class inheritance.
Q: What is the difference between overloading and overriding?

Overloading: same function name, different parameters, same class, resolved at compile time.

Overriding: derived class provides new implementation of a virtual function from base class, same signature, resolved at runtime.
Q: Can static functions be virtual?

No. Static functions have no this pointer and are resolved at compile time. Virtual functions need runtime dispatch via vtable (which requires this pointer). Contradiction — cannot be both.
Q: What is a friend function/class?

A function/class declared as friend inside a class can access private and protected members of that class. Not a member, not inherited. Use sparingly — breaks encapsulation.

8C. STL — Standard Template Library
Q: What is the difference between vector and list?

vector: dynamic array, O(1) random access, O(n) insert/delete in middle, cache-friendly (contiguous memory).

list: doubly linked list, O(1) insert/delete anywhere (with iterator), O(n) random access, not cache-friendly.

Use vector by default. Use list only when frequent middle insertions.
Q: What is the difference between map and unordered_map?

map: red-black tree (balanced BST), O(log n) all operations, keys sorted.

unordered_map: hash table, O(1) average all operations, O(n) worst case (hash collision), keys unordered.

Use unordered_map for speed. Use map when you need sorted keys or guaranteed O(log n).
Q: What is the difference between set and multiset?

set: unique elements, O(log n), sorted.

multiset: allows duplicates, O(log n), sorted.
Q: What are iterators? Types?

Objects that point to elements in containers. Types:

Input: read-only, single pass
Output: write-only, single pass
Forward: read/write, single pass forward
Bidirectional: read/write, forward and backward (list, set, map)
Random access: all above + jump to any element (vector, deque, array)

Q: What does std::move() do internally?

Casts an lvalue to an rvalue reference — does NOT actually move anything by itself. The move constructor/assignment then takes ownership of resources from the temporary, leaving the source in a valid but unspecified state. Critical for performance when returning large objects from functions.
Q: What is std::shared_ptr reference counting mechanism?

shared_ptr maintains a control block (on heap) with use_count and weak_count. Each copy increments use_count. Each destruction decrements it. When use_count reaches 0, object is deleted. Thread-safe for count operations but not for the pointed-to object itself.
Q: What is a circular reference with shared_ptr? How to break it?

If A holds shared_ptr to B, and B holds shared_ptr to A, use_count never reaches 0 — memory leak. Fix: one side uses weak_ptr. weak_ptr does not increment use_count; call lock() to get a temporary shared_ptr.

8C. EXCEPTIONS & ERROR HANDLING
Q: What is exception handling? How does it work?

try-catch-throw. When throw executes, stack unwinding begins — destructors of all local objects are called as stack frames are popped, until a matching catch block is found. RAII ensures resources released during unwinding.
Q: What is std::exception? Hierarchy?

Base class for all standard exceptions. Derived: std::runtime_error, std::logic_error, std::bad_alloc (new failure), std::out_of_range, std::invalid_argument. Always catch by reference: catch (const std::exception &e).
Q: When should you NOT use exceptions?

In kernel code (no exception support). In real-time systems (unpredictable timing). In destructors (can cause terminate() if another exception is propagating). In performance-critical tight loops.

8D. CONCURRENCY (Very relevant to your daemon work)
Q: What is std::thread? How to create one?
#include <thread>
void worker(int id) { /* ... */ }
std::thread t(worker, 1);
t.join();    // wait for thread to finish
t.detach();  // let it run independently
Q: What is std::mutex? std::lock_guard?

mutex: provides mutual exclusion. lock()/unlock().

lock_guard: RAII wrapper — locks in constructor, unlocks in destructor. Cannot be manually unlocked. Never throws past unlock.

unique_lock: more flexible — can unlock/relock manually, works with condition_variable.
Q: What is std::atomic?

Guarantees atomic read-modify-write operations without locks for primitive types. No data race by definition. Faster than mutex for simple counters/flags. std::atomic<int> counter{0}; counter++; is thread-safe.
Q: What is a condition variable?

Allows threads to wait until a condition is true. Used with unique_lock.
std::condition_variable cv;
std::mutex mtx;
bool ready = false;

// Consumer thread:
std::unique_lock<std::mutex> lk(mtx);
cv.wait(lk, []{ return ready; }); // releases lock while waiting

// Producer thread:
{ std::lock_guard<std::mutex> lk(mtx); ready = true; }
cv.notify_one();
Q: What is a deadlock? Give a real example from systems programming.

Thread A holds lock1, waits for lock2. Thread B holds lock2, waits for lock1. Neither can proceed. Real example: two threads each trying to lock a socket and a file descriptor in opposite order. Fix: always acquire locks in the same global order.
Q: What is a data race vs race condition?

Data race: two threads access same memory simultaneously, at least one writes, no synchronization. Undefined behaviour in C++.

Race condition: program correctness depends on timing of events. A data race is one type. A race condition can exist without a data race (e.g., TOCTOU — time-of-check to time-of-use). Your DLP printer module had to reason about TOCTOU in spool file handling.
SECTION 9 — OS INTERNALS DEEP DIVE

9A. PROCESS & MEMORY MANAGEMENT
Q: What is copy-on-write (COW) in fork()?

After fork(), parent and child share the same physical memory pages (marked read-only). When either writes to a page, the kernel makes a private copy for the writer. Avoids copying entire process memory on every fork — crucial for efficiency. exec() after fork() triggers COW for all pages.
Q: What is the difference between stack overflow and heap overflow?

Stack overflow: recursive calls or large local arrays exceed stack size limit (~1-8MB). Usually SIGSEGV. Infinite recursion is the common cause.

Heap overflow: writing beyond malloc'd buffer into adjacent heap metadata or other allocations. Exploitable for code execution.
Q: What are the segments of a process in memory?

From low to high address (typical Linux):

Text (code) segment: read-only, executable — machine instructions
Data segment: initialized global/static variables
BSS segment: uninitialized global/static variables (zeroed at startup)
Heap: grows upward, dynamic allocation
Stack: grows downward, function call frames, local variables
Kernel space: mapped but inaccessible to user (top of address space)

Q: What is mprotect()? How is it used in security?

System call that changes memory page protections (PROT_READ, PROT_WRITE, PROT_EXEC). Used in security to: implement W^X (write XOR execute — a page is either writable or executable, never both), protect JIT-compiled code, implement stack canaries. Relevant to your binary integrity work.
Q: What is ASLR?

Address Space Layout Randomization — randomizes base addresses of stack, heap, and libraries at each execution. Makes exploitation harder — attacker cannot predict where shellcode or libc functions are. Can be disabled per-process with personality(ADDR_NO_RANDOMIZE) — useful in debugging.
Q: What is a core dump?

Snapshot of process memory at the time of a crash (SIGSEGV, SIGABRT etc.). Contains register state, call stack, heap/stack contents. Analyzed with GDB: gdb ./program core. Your fanotify-based security work should not interfere with core dump generation.
Q: What is the difference between paging and segmentation?

Paging: divides memory into fixed-size pages (typically 4KB). Physical/virtual split. No external fragmentation. OS manages page tables.

Segmentation: divides memory into variable-size logical segments (code, data, stack). Can have external fragmentation. x86 uses segmentation + paging together.
Q: What are huge pages (THP)?

Instead of 4KB pages, use 2MB or 1GB pages. Reduces TLB misses (fewer entries needed for same memory). Linux Transparent Huge Pages (THP) can do this automatically. Relevant in high-performance daemons.

9B. FILE SYSTEM INTERNALS
Q: What is the VFS (Virtual File System)?

Abstraction layer in the Linux kernel that provides a uniform interface for different filesystem types (ext4, NTFS, tmpfs, procfs). Your fanotify hooks at the VFS layer — works regardless of underlying filesystem.
Q: What is /proc filesystem?

Virtual filesystem exposing kernel and process information as files. /proc/PID/maps: memory map. /proc/PID/fd: open file descriptors. /proc/meminfo: memory stats. /proc/net/: network info. Your kernel modules can read /proc entries.
Q: What is the difference between buffered and unbuffered I/O?

Buffered (stdio): data goes through userspace buffer (FILE*). Writes batched and flushed periodically. fflush() forces flush.

Unbuffered (syscall): write() goes directly to kernel. No userspace buffer. Always immediately visible to kernel. Your daemon uses write() directly for reliability.
Q: What is fsync() and why is it needed?

Forces kernel to flush all buffered writes for a file descriptor to disk. write() just writes to kernel page cache — fsync() persists to physical storage. Critical for databases, audit logs, your FIM baseline snapshot.
Q: What is an epoll? How is it different from select/poll?

epoll: Linux-specific, O(1) for checking ready file descriptors, edge-triggered or level-triggered, scales to millions of FDs.

select: O(n) scan, limited to 1024 FDs, not scalable.

poll: O(n) scan, no FD limit, but still not scalable.

Your daemon likely uses a poll/epoll loop to monitor the fanotify file descriptor.

9C. SIGNALS & IPC
Q: What are signals? Give 5 important ones.

Asynchronous notifications to a process.

SIGKILL (9): cannot be caught or ignored, immediate kill — your kernel module sends this to ransomware
SIGTERM (15): polite termination request, can be caught for cleanup
SIGSEGV (11): segmentation fault — invalid memory access
SIGCHLD: sent to parent when child terminates
SIGUSR1/SIGUSR2: user-defined, commonly used for daemon reload/status

Q: What is signal()/sigaction()? Which is better?

signal(): simple, but behaviour varies across systems, non-reentrant.

sigaction(): portable, more control (blocking signals during handler, SA_RESTART for syscall restart, SA_SIGINFO for extra info). Always prefer sigaction() in production code.
Q: What are the IPC mechanisms in Linux?

Pipes: anonymous (parent-child), half-duplex
Named pipes (FIFOs): unrelated processes, filesystem path
Unix domain sockets: bidirectional, faster than TCP, your scanner uses this
Message queues (System V / POSIX): structured messages, persist until deleted
Shared memory: fastest, needs explicit synchronization (mutex/semaphore)
Semaphores: synchronization primitive
Signals: notification only, no data
Memory-mapped files: file-based shared memory via mmap()

Q: What is a pipe buffer size? What happens when it's full?

Default pipe buffer: 64KB on Linux. When full, write() to the pipe blocks until the reader consumes data. This is backpressure — relevant when your fanotify daemon processes events slower than they're generated.

SECTION 10 — COMPUTER NETWORKS DEEP DIVE

10A. TCP/IP IN DEPTH
Q: What is TCP flow control? Congestion control?

Flow control: prevents sender from overwhelming receiver. TCP uses sliding window — receiver advertises window size (how much buffer it has). Sender cannot send more than window size unacknowledged.

Congestion control: prevents sender from overwhelming the network. Algorithms: Slow Start, Congestion Avoidance, Fast Retransmit, Fast Recovery (TCP Reno/CUBIC).
Q: What is the difference between latency and bandwidth?

Latency: time for a packet to travel from source to destination (milliseconds).

Bandwidth: amount of data that can be transferred per second (Mbps/Gbps).

A satellite link has high bandwidth but high latency. A fast LAN has high bandwidth and low latency.
Q: What is TIME_WAIT state in TCP? Why is it 2*MSL?

After sending the final ACK in connection teardown, the socket stays in TIME_WAIT for 2*MSL (Maximum Segment Lifetime, typically 2 minutes). Reason: ensures the final ACK was received (if not, remote sends FIN again). Also ensures old packets from this connection die before a new connection on same port.
Q: What is Nagle's algorithm?

TCP optimization that combines small writes into larger segments — waits before sending if there's unacknowledged data. Reduces packet count but adds latency. Disabled with TCP_NODELAY socket option. Important for your Unix socket IPC — disable Nagle for low-latency scan results.
Q: What is a SYN flood attack? How to prevent?

Attacker sends many SYN packets without completing handshake — fills server's SYN queue, legitimate connections rejected. Prevention: SYN cookies (encode connection state in sequence number instead of memory), reduce SYN_RCVD timeout, increase backlog queue, rate limiting.
Q: What is the difference between ICMP and ping?

ICMP (Internet Control Message Protocol): Layer 3 protocol for network diagnostic/error messages. Ping uses ICMP Echo Request and Echo Reply to test reachability and measure RTT.
Q: What is MTU? What is fragmentation?

Maximum Transmission Unit: largest packet size a network link can carry (Ethernet default: 1500 bytes). If IP packet exceeds MTU, it's fragmented into smaller pieces. Reassembled at destination. IPv6 doesn't allow router fragmentation — uses Path MTU Discovery instead.
Q: What is a VLAN?

Virtual LAN — logically partitions a physical network into separate broadcast domains. Configured on switches. Traffic between VLANs requires a router. Used for security isolation, traffic management. Your pf firewall project deals with zone-based rules which are conceptually similar.

10B. NETWORK SECURITY
Q: What is a man-in-the-middle attack?

Attacker intercepts communication between two parties, can read or modify data. Prevention: TLS/SSL with certificate validation, public key pinning, HSTS.
Q: What is ARP poisoning?

Attacker sends fake ARP replies linking their MAC to a legitimate IP address. Causes traffic to be redirected to attacker. Used for MITM on local networks. Prevention: dynamic ARP inspection, static ARP entries.
Q: What is a replay attack?

Attacker captures a valid message/token and retransmits it later. Prevention: nonces (numbers used once), timestamps, session tokens. Your Ed25519 signatures don't prevent replay (same binary signed with same key) — you need version numbers or timestamps for that.
Q: What is SQL injection?

Attacker inserts SQL commands into input fields that get executed by the database. Example: ' OR '1'='1 in login field. Prevention: parameterized queries / prepared statements, input validation, stored procedures.
Q: What is a buffer overflow exploit?

Q: What is the difference between authentication and authorization?

Malware that hides its presence and maintains privileged access.

Q: What is select() used for?

Monitors multiple file descriptors simultaneously — returns when one or more are ready for read/write. Used in single-threaded servers handling multiple clients. Limited to 1024 FDs. Your daemon likely uses poll() or epoll() which are more scalable.
Q: What is htons()? Why is it needed?

Host TO Network Short — converts 16-bit integer from host byte order to network byte order (big-endian). Network protocols use big-endian. x86 is little-endian. Always use htons() for port numbers, htonl() for IPv4 addresses in socket structs.
Q: What is SO_REUSEADDR?

Socket option that allows binding to a port that's in TIME_WAIT state. Without it, restarting a server fails with "Address already in use" for ~2 minutes after shutdown. Always set this on server sockets.

SECTION 11 — DBMS (Database Management Systems)
Q: What is ACID?

Atomicity: transaction is all-or-nothing. Either all operations commit or none do.
Consistency: database goes from one valid state to another. Constraints never violated.
Isolation: concurrent transactions don't interfere with each other.
Durability: committed transactions survive crashes (written to disk).

Your SQLite FIM baseline uses ACID — if daemon crashes mid-update, snapshot remains consistent.

Q: What is normalization? Forms?

Process of organizing data to reduce redundancy.

1NF: atomic values, no repeating groups
2NF: 1NF + no partial dependencies (all non-key columns depend on entire primary key)
3NF: 2NF + no transitive dependencies (non-key columns don't depend on other non-key columns)
BCNF: stricter 3NF

Q: What is a transaction? How do you write one in SQL?
BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 500 WHERE id = 1;
UPDATE accounts SET balance = balance + 500 WHERE id = 2;
COMMIT;
-- or ROLLBACK; if something fails
Q: What is an index? How does B-tree index work?

B-tree (Balanced tree) index: self-balancing tree where internal nodes act as guides and leaf nodes contain data pointers. Keeps data sorted, allows O(log n) search, insert, delete. Range queries are efficient. Your SQLite FIM uses B-tree index on file path.
Q: What is a stored procedure?

Precompiled SQL code stored in the database and executed by name. Advantages: reduced network traffic, reusable logic, security (users call procedure without direct table access), performance (precompiled execution plan).
Q: What is a trigger?

SQL code that automatically executes in response to INSERT, UPDATE, or DELETE on a table. Used for audit logging, enforcing complex constraints, cascading changes.
Q: What is the difference between INNER JOIN and OUTER JOIN?

INNER JOIN: only rows that match in both tables.

LEFT OUTER JOIN: all rows from left table + matched rows from right (NULL for unmatched).

RIGHT OUTER JOIN: all rows from right table + matched rows from left (NULL for unmatched).

FULL OUTER JOIN: all rows from both tables (NULL where no match on either side).
Q: What is a deadlock in databases?

Transaction A holds lock on row 1, waits for row 2. Transaction B holds lock on row 2, waits for row 1. Database detects this and rolls back one transaction (victim). Different from OS deadlock — database handles it automatically.
Q: What are isolation levels?

Controls what a transaction can see from other concurrent transactions.

Read Uncommitted: can read uncommitted changes (dirty reads possible)
Read Committed: only reads committed data (most DBs default)
Repeatable Read: same row returns same value in a transaction
Serializable: strictest — transactions appear to run serially


SECTION 12 — DATA STRUCTURES DEEP DIVE
Q: What is a hash table? How does it handle collisions?

Array + hash function. Hash function maps key to array index. Collisions (two keys map to same index) handled by:

Chaining: linked list at each slot
Open addressing: probe for next empty slot (linear, quadratic, double hashing)

Load factor = elements / slots. Resize (rehash) when load factor > 0.7.

Q: What is a heap? Min-heap vs max-heap?

Complete binary tree where parent is always smaller (min-heap) or larger (max-heap) than children. Not sorted — just the heap property. Used in priority queues, heap sort, Dijkstra's algorithm. Insert: add at end, bubble up. Delete min/max: replace root with last, bubble down. O(log n) operations.
Q: What is a trie? When to use it?

Tree where each node represents a character. Root to leaf spells a word. O(L) search where L = word length. Used for: autocomplete, spell check, IP routing tables (prefix matching). Relevant to your PCRE2 pattern matching work.
Q: What is dynamic programming? Difference from recursion with memoization?

DP: breaking problem into overlapping subproblems, solving each once, storing results.

Memoization (top-down DP): recursive solution + cache. Lazy — only computes needed subproblems.

Tabulation (bottom-up DP): iterative, fills table from base cases. No recursion overhead.
Q: What is amortized analysis?

Average cost per operation over a sequence of operations, even if individual operations vary. Example: dynamic array doubling — individual resize is O(n) but amortized over n pushes = O(1) per push. Your event queue processing uses similar reasoning.
Q: What is the difference between DFS and BFS complexity?

Both: Time O(V+E) where V = vertices, E = edges.

Space: BFS uses O(V) for queue (worst case all vertices in queue). DFS uses O(V) for stack/recursion (depth of tree). For wide graphs, DFS uses less memory. For deep graphs, BFS uses less memory.

PUZZLE 16: Coin change problem (DP)

Minimum coins to make amount N.
int minCoins(int coins[], int n, int amount) {
    int dp[amount+1];
    dp[0] = 0;
    for (int i = 1; i <= amount; i++) dp[i] = INT_MAX;
    for (int i = 1; i <= amount; i++)
        for (int j = 0; j < n; j++)
            if (coins[j] <= i && dp[i - coins[j]] != INT_MAX)
                dp[i] = min(dp[i], dp[i - coins[j]] + 1);
    return dp[amount];
}

PUZZLE 20: Longest common subsequence (DP)
int lcs(char* s1, char* s2, int m, int n) {
    int dp[m+1][n+1];
    for (int i = 0; i <= m; i++) {
        for (int j = 0; j <= n; j++) {
            if (!i || !j) dp[i][j] = 0;
            else if (s1[i-1] == s2[j-1]) dp[i][j] = dp[i-1][j-1] + 1;
            else dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
        }
    }
    return dp[m][n];
}
SECTION 14 — SECURITY-SPECIFIC QUESTIONS (Your domain — expect deep questions here)
Q: What is the difference between EDR and antivirus?

Antivirus: signature-based, detects known malware by hash/pattern. Reactive.

EDR (Endpoint Detection and Response): behavior-based monitoring, records process activity, network connections, file operations, detects anomalies. Your eScan EDR work is this — fanotify, ESF, and syscall hooks enable behavioral detection.
Q: What is code signing? Why is it important?

Attaching a cryptographic signature to a binary to prove it came from a known source and hasn't been tampered with. Your Guardian project implements this with Ed25519. macOS and Windows both require code signing for apps to run without warnings. Prevents supply chain attacks.
Q: What is the principle of least privilege?

Give any process, user, or system only the minimum permissions needed to perform its function. Your fanotify daemon runs as root (needed for FAN_OPEN_PERM) but could drop capabilities after initialization. Reducing attack surface.
Q: What is a race condition in security context (TOCTOU)?

Time-Of-Check to Time-Of-Use: check a condition (e.g., file exists and is safe) then use it — attacker replaces file between check and use. Your DLP printer scanner must handle this: check spool file → verify content → delete. If another process replaces the spool file between check and delete, wrong file gets deleted. Fix: open file once, operate on the open fd.
Q: What is defense in depth?

Multiple independent security layers so that failure of one doesn't compromise the system. Your ransomware module demonstrates this: lsmod hiding + passphrase sysfs + SIGKILL on detection + JSON audit log. Each layer adds cost for attacker.
Q: What is the difference between symmetric and asymmetric encryption?

Symmetric: same key for encrypt/decrypt (AES). Fast, used for bulk data. Key distribution is the problem.

Asymmetric: public key encrypts, private key decrypts (RSA). Or private key signs, public key verifies (Ed25519). Slow, used for key exchange and signatures. Key distribution solved — public key can be shared freely.
Q: What is a hash collision? How does it affect your FIM?

Two different inputs produce the same hash output. MD5 has known collision attacks — attacker could craft a malicious file with the same MD5 hash as a legitimate file. Your FIM uses MD5 (your resume mentions this) — upgrade path is SHA-256 which has no practical collisions. Mention this proactively — shows awareness.
Q: What is a kernel module attack surface?

Your kernel module runs in ring 0 — any bug is a privilege escalation or system crash. Attack surface includes: sysfs interface (your password-protected interface), ioctl handlers, probe functions, symbol exports. Must validate ALL userspace input before using it in kernel context — never trust userspace data size/pointer.

SECTION 16 — WINDOWS SDK / KMDF (Gap area — know enough to not fail)
Q: What is the difference between WDM and KMDF?

WDM (Windows Driver Model): older, complex, manual IRP handling, error-prone.

KMDF (Kernel-Mode Driver Framework): higher-level wrapper over WDM, handles IRP complexity, plug-and-play, power management automatically. Use KMDF for new drivers. Equivalent to saying: WDM is like raw syscalls, KMDF is like using a framework.
Q: What is an IRP?

I/O Request Packet — the fundamental communication structure between Windows I/O manager and drivers. Equivalent to a struct carrying the I/O request (read, write, ioctl). Drivers receive IRPs, process them, and either complete or pass to next driver in the stack. Analogous to your fanotify event + response pattern.
Q: What is a minifilter driver? How does it relate to your fanotify work?

Minifilter: Windows kernel component that attaches to the file system filter manager to intercept file I/O. Exact equivalent of your Linux fanotify work. Pre-operation callback = your FAN_OPEN_PERM handler. Post-operation callback = your NOTIFY_CLOSE handler. FltRegisterFilter() is the Windows equivalent of fanotify_init().
Q: What is IOCTL?

I/O Control — mechanism for userspace to send commands and receive data from a kernel driver. Defined by control code (CTL_CODE macro on Windows, ioctl() on Linux). Your sysfs password interface on Linux is the equivalent — userspace writes password to a sysfs file; Windows equivalent would be a DeviceIoControl() call.
Q: What is the Win32 API equivalent of fork()?

Windows has no fork(). Instead: CreateProcess() creates a new process from scratch. CreateThread() creates a thread. For process-based parallelism, Windows uses spawn pattern (CreateProcess) not fork+exec pattern.

SECTION 19 — QUICK CONCEPT DEFINITIONS FOR MCQ
What is a semaphore initialized to 1?

Binary semaphore — acts like a mutex but without ownership. First wait() decrements to 0, blocks others. Signal() increments back to 1.
What is Belady's anomaly?

With FIFO page replacement, increasing the number of frames can sometimes increase page faults. Does NOT occur with LRU or Optimal.
What is critical section problem requirements?

Must satisfy: Mutual exclusion (only one process inside at a time), Progress (if no one inside, waiting process must be able to enter), Bounded waiting (no starvation — process must eventually enter).
What is the banker's algorithm?

Deadlock avoidance algorithm — checks if allocating a resource leads to a safe state (where all processes can eventually finish). Keeps system in safe state at all times.
What is a race condition in the kernel?

Two CPU cores accessing the same kernel data structure simultaneously without locking. On single-core with preemption: interrupt handler and process context. Fix: spinlocks (in interrupt context), mutexes (in process context), RCU for read-heavy data.
What is cache coherence?

In multi-core CPUs, each core has its own L1/L2 cache. When one core writes to a memory location, other cores' cached copies become stale. Cache coherence protocols (MESI) ensure all cores see a consistent view of memory. Relevant to your atomic operations and memory ordering.
What is memory ordering?

CPU and compiler can reorder memory operations for performance. std::atomic with memory_order_relaxed gives no ordering guarantees. memory_order_acquire/release creates synchronization points. memory_order_seq_cst gives total ordering (default, safest). Use in your daemon's atomic flag for shutdown signaling.
What is the difference between process scheduling and memory management?

Process scheduling: decides which process/thread runs on CPU (scheduler).

Memory management: manages virtual-physical address mapping, paging, swapping (memory manager / VMM).

Both are core OS kernel subsystems.
What is copy-on-write in C++ strings?

Pre-C++11: some implementations shared string buffer until a write occurred, then made a copy. C++11 mandates separate storage — COW is no longer allowed for std::string due to thread safety issues.
What is RVO (Return Value Optimization)?

Compiler optimization — when a function returns a local object, compiler constructs it directly in the caller's space instead of copying. Avoids copy/move constructor call entirely. Guaranteed since C++17 (NRVO is optional).
